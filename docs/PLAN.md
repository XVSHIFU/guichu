# 归处：从 MVP 到可用的本机管理平台

日期：2026-10-03。状态：P0–P4 本轮计划已交付并完成分层验收。真实兼容 API 的工具问答、取消与历史已验证；修改和恢复使用隔离配置/数据库验证，不据此宣称已修改用户软件。后文为各阶段历史记录，最新验收见第17节。

## 1. 要交付什么

统一查看软件、Agent、Skill、MCP 和目录；从一个对象进入助手，保存讨论与方案，在明确目标、看过变更后执行受支持的操作，并能追溯结果。

用户操作主线：**发现对象 → 侧边简览 → 详情或助手 → 查看方案 → 确认变更 → 执行结果／恢复记录**。

保留已确认的界面：侧栏搜索与设置；列表选中只更新简览，点击简览再开抽屉；A–Z／中文拼音排序；软件分类；本机图标；按磁盘逐层浏览；浅深色与键盘操作。先复用 React、Radix、Python、SQLite，不重做外观、不换技术栈。

## 3. 开发阶段与完成条件

### P0：建立稳定基线与接口约定

**交付：** 可继续开发的骨架、数据库迁移入口、约定好的对象／会话／任务契约。

- 保留当前可用版本和数据库备份；在临时数据库验证迁移和恢复。
- 只拆即将共同修改的部分：页面壳、助手页面、数据库访问、API 分派与采集服务；不为了形式拆所有文件。
- 扫描对象明确来源、检查时间、检查结果；失败时保留最后成功证据并标注过期，不把读失败当删除。
- 目录刷新保留旧内容、错误与忙碌状态分开；分页使用短期枚举快照／游标，切换目录使旧请求结果失效。
- 校正文档和相关测试；明确演示模式与真实模式。
- 图标提取改为可失败的增强任务，不阻塞清单发布；保留超时、退出码和脱敏错误，避免未来并发任务共用一个临时清单文件。

**验收：** 现有查看／备注／简览／抽屉不回退；单一来源失败不删除其他来源对象；目录分页无重复或漏项；迁移不丢备注；数据库恢复后可启动。

### P1：助手历史记录（首个用户可见里程碑）

**交付：** 历史列表 → 打开会话 → 继续对话。

- 会话标题、最近更新时间、关联对象、搜索、重命名、新建、删除与空状态。
- 消息、草稿、上下文与提案存 SQLite；页面切换和重启后恢复；当前仍允许演示模式，但历史明确标记演示来源。
- 用户发送后先落盘；失败提供重试，重复提交不产生重复消息。
- 切换会话不改变在途任务的目标。历史目标已不存在时保留当时名称与路径摘要，不能自动改绑新对象。
- 删除会话与删除电脑文件严格分开；有活动任务时先取消或阻止删除，不静默丢掉任务入口。
- 现有 `tests/assistant.mjs` 的“零 POST”只适用于演示原型；历史保存接入后改为“允许会话数据写入、禁止修改被管理对象”，按真实副作用验收。

**验收：** 发送 → 切页 → 重启 → 重新打开内容一致；两个会话交替编辑不串草稿；搜索／重命名／删除可用；历史不是仅靠浏览器缓存保存。

### P2：真实只读助手

**交付：** 助手能基于本机真实证据回答“这是什么、谁在用、有哪些配置”，引用对象和检查时间。

- 先定义能力表，再做一个模型适配器的最小切片；此阶段再查所选 SDK 的官方接口与版本，不在计划中假定订阅、CLI 或 API 可互换。
- 仅接一个用户实际可用的提供方／运行方式；模型设置、连接测试、密钥安全存储、错误反馈一起交付。
- 工具首批仅限：对象检索、详情与关系、已授权配置的脱敏摘要、当前目录元信息；查询范围由服务端解析对象 ID。
- 增加流式回答、工具事件、取消、超时、调用次数／费用预算；任务与页面生命周期分离。
- 只在用户仍跟随最新内容时自动滚动。异常、取消、断线、恢复分别呈现。
- 用户选择模型前说明哪些本机摘要会发送到该服务；密钥不进前端、日志或会话。技能正文是参考资料，不作为授权来源。

**验收：** 一次真实“请求 → 只读工具 → 有来源的回答”通过；越界读取被拒绝；离线／无效密钥／超时可理解；取消后不再继续调用；切会话不串结果。没有有效凭据时只能报告模拟测试通过，不能算真实接入完成。

### P3：第一条真实修改闭环

**交付：** 用一个可恢复的动作打通全流程，再扩展动作数量。

- 首先用工作台内部“分类／保留决定”验证提案、确认与记录。
- 首个外部配置动作候选：在明确的宿主配置中启用／停用一个 Skill 或 MCP；先核对该宿主的实际配置格式、作用域与是否支持，支持后只选一种实现。
- 服务端生成目标、变更前后差异、影响范围与备份位置。确认绑定提案版本和原文件摘要，模型不能自己批准。
- 执行前重新核对原文件；若用户或其他程序已修改，停止并重新生成提案。
- 固定动作处理器执行，写前备份、尽可能原子写入、写后回读验证、刷新清单。支持恢复但不承诺跨文件全原子事务。
- 双击／网络重试靠幂等键去重；部分成功逐项记录；取消不冒充已回滚；恢复前同样检查是否覆盖后续修改。

**验收：** 临时配置中的预览／确认／执行／恢复闭环通过；过期提案、重复请求、写失败、部分成功有正确状态。真实本机写入只对用户确认的具体目标进行，不能把本计划视为批量清理授权。

### P4：扩展覆盖与交付日常版

- 根据实际使用增加：便携软件来源、项目级配置、可取消的目录大小统计、分类纠错与关联维护。
- 软件卸载与目录回收单独增加动作适配器：核对使用状态、明确删除范围、优先官方卸载或回收站、记录恢复限制。
- 明确启动／停止／端口冲突／日志位置；备份恢复和版本迁移可操作。
- 有真实安装分发需求后再决定是否做桌面壳。第一版不做跨设备同步、云账号、多用户、全盘常驻索引或通用终端执行。

**验收：** 用户可以完成一次日常“查看 → 询问 → 确认 → 修改 → 回看结果”，并能找到历史、失败原因和恢复入口。

## 4. 核心边界与数据约定

```text
React 界面（清单 / 简览 / 抽屉 / 对话与历史）
                   ↓ 受限 API
Python 本机服务（对象证据 / 会话 / 任务 / 策略 / 固定动作）
           ↓                     ↓
SQLite 权威状态             模型适配器 / 本机采集与执行
```

- SQLite 是已保存状态的唯一权威来源；浏览器保存主题、临时界面状态和明确标记的离线缓存。
- 分开保存“采集事实”“人工决定”“模型建议”，不得互相覆盖。
- 会话：`id / title / mode / created_at / updated_at`；消息绑定 `session_id`，附对象快照引用。草稿按会话保存。
- 任务：`task_id / session_id / target_ids / scope / input_revision / status`；事件有递增序号，支持断线后续读。
- 提案：绑定任务、动作类型、前后差异、原始摘要、确认版本；执行记录另存，不靠聊天文本判断是否完成。
- 状态至少区分：排队、运行、等待确认、成功、失败、取消、部分成功；服务重启后的中断任务不自动重放写操作。
- 现有进程内 `SCAN` 逐步纳入同一任务记录；扫描去重、失败和重启状态可追溯，不另外维护一套漂移的运行真值。
- API 先约定会话 CRUD、消息提交、任务读取／取消、事件续读；P3 再加提案确认、执行和恢复接口。接口名称在 P0 固定，避免两端各自设计。
- 当前目录浏览不等于授权模型读取任意文件。模型只提交业务标识，服务端验证路径、作用域与文件版本；不提供任意 shell／任意代码执行。

## 5. Agent-team 分工与并行方式

同时最多运行主 Agent 加三个子 Agent；角色按阶段复用，不同时开全部角色。

| 角色 | 负责结果与文件范围（拟定） | 不负责 |
| --- | --- | --- |
| 主 Agent／集成负责人 | `PLAN.md`、API 契约、`main.jsx` 页面壳、启动入口、集成与发布检查 | 不把模块任务交叉写给多个 Agent |
| A：数据与采集 | `app/backend/storage/`、`inventory/`、`filesystem/`，数据库迁移及后端相关测试 | 不改助手界面，不接模型 |
| B：前端与交互 | `app/src/features/assistant/`、历史页、简览到助手衔接、局部样式与前端测试 | 不自行改变 API、数据库结构与执行权限 |
| C：助手与执行 | `app/backend/assistant/`、模型适配、任务事件；P3 增加 `actions/` 和恢复测试 | 不代用户确认，不调用任意系统命令 |
| 复核角色（阶段收尾时复用空闲槽位） | 只读检查跨模块流程，运行明确的集成／故障场景，向主 Agent 报告证据 | 不重复开发或无范围地全仓重构 |

目录是拟定职责边界，尚未创建；P0 由主 Agent 完成最小拆分后交接。`server.py`、`main.jsx`、共享样式和依赖锁文件先由主 Agent 独占整合；新模块各自拥有局部文件，避免同时堆叠修改。

并行顺序：

1. **P0 主 Agent 固定契约与拆分**；A 审视数据迁移，B 对照用户确认的交互。
2. **P1 A 做会话存储/API，B 用同一契约做历史界面**；C 准备可控任务状态，不接真实写操作。模拟接口验证必须与真实接口联调区分。
3. **P2 C 做只读助手，A 提供证据工具，B 连接流式与任务状态**；主 Agent 统一集成。
4. **P3 先主 Agent 固定动作范围，再 A/C 实现执行与恢复、B 做差异确认**；通过后扩展。
5. **每阶段一次相关验收**，有失败修复后复测；无新风险不反复扩大检查。

每个任务交接包含：目标、输入契约、可写文件、依赖、完成标准；回报包括改了什么、测试证据和未解决事项。跨范围修改先向主 Agent 协调，不覆盖其他 Agent 的工作。
